# 研究说明

本文说明「从鲛人到美人鱼——关于神话形象的跨文化重构的可视化研究」（以下简称本项目）的定位、问题意识、收录标准、方法路径与使用方式。字段定义与技术约定不在本文重复，见《项目约定》（`docs/CONVENTIONS.md`）；编码细则见《编码手册》（`docs/编码手册.md`）；文献见《参考书目》（`docs/参考书目.md`）。网站「研究说明」页（`#/about`）为本文的网页版，供检索时随时回看。

## 一、项目定位

本项目是一份面向中文人文学者的专题研究数据库，立足中国民间文学，兼采比较文学与神话学的问题意识。研究对象是鲛人、人鱼、美人鱼、塞壬（Siren）、人魚 等一组彼此相关而并不等同的形象。它们分属不同的语言与信仰传统，却在长期的翻译、传教、印刷、影视与商业传播中相互覆盖，在当代汉语读者的印象里逐渐合并为「人首鱼身的美人」这一意象。

本项目不打算编写一部定本辞书，也不以收罗异闻为目的。它更接近一份可检索、可比较、可复核的研究档案：每条材料被拆解为若干可编码的形态特征、能力特征与叙事功能，材料之间的异同因此可以被并置阅读，而不必依赖「西方美人鱼」与「中国鲛人」一类印象式概括。这一设计的出发点是：跨文化形象的变化往往不发生在某一条著名文本内部，而发生在大批彼此转述、误读与改写的中间材料之间。把中间材料并置，比复述结论更有研究价值。

## 二、四个研究问题

本项目的问题意识由「名称」「外形」「功能」「机制」四层构成。网站首页、资料库筛选与并置比较页均按此四层组织。

**其一，名称的滑动。** 「鲛人」「人鱼」「美人鱼」在汉语中并非自古同义，各有其文献谱系与类属边界；「塞壬」「海妖」「Siren」「mermaid」在译入汉语时又不断与上述词语交叉。名称的替换不是简单的意译选择，它往往同时改变了形象的善恶定性、性别归属与叙事位置。本项目把每一次定名、改译、类属合并都当作可追踪的事件。

**其二，外形的趋同与留存。** 古希腊古风时期的塞壬为人首鸟身，与鱼尾无关；中国六朝文献中的鲛人重在「水居」「织绩」「泣珠」，形体细节反而简略。鱼尾人形的组合是在漫长的图像传播与文本转述中逐渐成为默认形态的。哪些特征被保留，哪些被合并，哪些在跨媒介时被删除，需要逐条比对而不是整体断言。

**其三，叙事功能的重组。** 泣珠、织绡、报恩、诱惑、婚恋、牺牲、长生、生态受难等叙事功能并不稳定地附着于同一形象。功能随媒介与意识形态迁移：志怪中的鲛人以物产与交换为主，希腊塞壬以声音与死亡为主，十九世纪童话把牺牲与灵魂问题推到前台，二十世纪以后的影视与游戏则更多处理身份、生态与他者化。本项目关心的正是功能如何从一种形象转移到另一种形象。

**其四，变化机制。** 翻译、宗教（尤其基督教对塞壬的寓意化）、印刷与图像复制、影视动画工业、游戏与旅游、品牌与商业设计，各自以不同方式参与形象的再编码。机制层面的问题是本项目区别于一般形象罗列的关键：不仅要问「变成了什么」，还要问「经由什么环节、由谁、为谁而变」。

## 三、术语约定

项目内部严格区分以下指称。条目中的 `term.primary`、`term.variants` 与 `term.original` 即按此约定填写；编码时的差异见《编码手册》第四节。

| 指称 | 所指范围 | 使用时须注意 |
|---|---|---|
| 鲛人 | 中国六朝以来文献中的水中异人，六朝文献又称「泉先」「泉客」 | 古汉语「鲛」亦指鲨鱼，须与「鲛人」区分；不宜与欧洲美人鱼直接等同 |
| 人鱼 | 汉语中类属较宽的词，可指鲛人一类异人，也可在博物学语境中指儒艮等海牛目动物 | 同一词在不同语境所指不同，须看上下文 |
| 美人鱼 | 现代汉语常用词，多与安徒生童话及影视改编相关 | 用作现代通俗类属词时，不自动适用于古籍条目 |
| 塞壬 | 古希腊 Σειρήν 的音译，亦译「西壬」；通俗语境常称「海妖」 | 早期图像为人首鸟身，与鱼尾无关；后世与美人鱼图像合流 |
| 海妖 | 通俗类属词，可指塞壬，也可泛指各类海怪 | 含义宽泛，仅作辅助标签，不作编码主词 |
| 人魚 | 日语词，汉字与汉语「人鱼」同形，谱系不同 | 多为鱼身人面，常与凶兆、长生传说相关；不可因汉字相同而并入中国鲛人系统 |
| Siren | 英语中对古希腊塞壬的沿用，兼指警报器与诱惑者 | 与 mermaid 在英语中亦长期混用，须按具体文献判断 |
| mermaid | 英语「美人鱼」，鱼尾人形 | 与 Siren 的合并发生在中世纪以后，编码时不可把鸟身特征回溯给所有 mermaid |

## 四、收录范围与三类条目

**收录标准。** 其一，与上述形象直接相关，且具备可编码的形态、能力或叙事信息。其二，有可核对的一手材料或权威二手来源，来源须能在 `sources` 字段中落到具体版本。其三，优先收录「中间环节」，即译名、译本、图像、改编与论评，因为这些材料最能显示形象的重构过程，而非只收录公认经典。

**不予收录。** 仅提及形象名称而无实质内容的一笔带过；无来源的网络传说汇编与营销文案；无法核对原文的长篇作品（必要时以论评条目处理，或在背景中提及而不单独立目）。

**物产与工艺背景。** 合浦采珠、「以人命易珠」一类材料不单独立目，仅在讨论泣珠、织绡的物质背景时引用；它们提示珍珠来自高风险劳动与贸易，而非仅海中异类的眼泪，可作为理解「泣珠」母题何以被反复书写的现实参照。

**三类条目。** 数据库以 `kind` 字段区分三类：

- 古籍与古典图像（`ancient`）：古籍原典、古典诗文、图像与器物。此类条目重在原文、卷次与版本，`excerpt` 为原文引文，`confidence` 多标「确证」或「版本存异」；本草与医书类归 `subtype: 医书`。
- 译名与译本（`translation`）：辞书译名、译本定名、跨语言命名与术语事件。此类条目重在「原词、译入语、译名、译名变化」四要素，须写明译名出处（某译本、某版字幕或某词典），不得只写「有人译作」。
- 当代作品与论评（`modern`）：影视、动画、游戏、舞台剧、小说、品牌与学术评论。此类条目重在改编选择与功能迁移，引文控制在合理引用范围内；舞剧与舞台剧归 `subtype: 舞台`、`medium: 舞台`。

**引文要求。** 典籍、图像、诗歌、译名类以及所有 `ancient` 条目必须提供原文或图版著录；影视、动画、游戏、舞台、商业、学术等以作品信息为主的条目可以不附原文，但须在 `summary` 末尾注明「本条目以作品信息为主，无原文引文」。

**邻近谱系条目。** 龙女、白秋练、两栖人、鱼尾狮、大鱼等材料并不属于鲛人、美人鱼或塞壬，但与上述形象共享水下居所、跨类婚恋、半人半鱼结构或商品化路径。此类材料按 `ancient` 或 `modern` 收录，并在 `term.note` 与 `summary` 中明确标注「邻近谱系」，只用于功能比较，不并入任何一条形象的谱系计数。

## 五、方法与可视化逻辑

**编码。** 每条材料按数据字典的 39 个 id 编码：9 项形态、17 项能力、13 项叙事；每条取 1 至 8 个特征（诗文用典与译名、译本类可仅 1 项）、1 至 3 个叙事。编码只记录材料明确支持的信息，不把后世通说回溯给早期文本。判定标准、正例、边界例与冲突处理规则见《编码手册》。

**并置比较。** 比较页允许同时选取二至四条材料，按形态、能力、叙事三组展示共现与差异。比较的单位是「特征是否出现」，而不是「谁更像美人鱼」，以避免以现代印象为标尺。

**时间轴。** 以 `year` 排序，按文化分组着色，并标注若干形态与命名的转折点。年代为约数者以 `yearNote` 说明，避免把估算值当作确证纪年。

**名称谱系。** 以 `term.primary`、`term.variants` 与 `term.original` 构成节点与连线，展示译名与类属的覆盖路径。谱系图表达的是文献中出现过的指称关系，不表示发生学上的先后。

**可视化能做什么，不能做什么。** 图表用于发现可疑的空白与聚集，例如某地区长期缺少鱼尾特征，或某功能在某一世纪突然密集出现。图表不能替代原文细读，编码的取舍仍需回到材料本身。

## 六、网站使用方式

站点为纯静态页面，双击 `index.html` 即可在浏览器中打开，无需服务器与网络。全部数据以脚本形式随页面加载，可离线检索。主要入口：首页（研究问题概览）、资料库（按 `kind`、文化、特征、叙事筛选与检索）、条目详情（原文、出处、编码、相关条目）、并置比较、时间轴、名称谱系、参考书目、研究说明。地址采用 hash 路由，可直接引用某一筛选状态或条目，例如 `#/entry/cn-bowuzhi-jiaoren`。

## 七、数据伦理与引用规范

**可信度分级。** 每条材料标 `confidence`：「确证」表示原文或官方信息可直接核对；「版本存异」表示存在版本、异文或归属争议，已在条目中注明；「待核」表示线索可靠但尚未逐字核对，引用前须复核。读者引用本项目时，应同时核对该字段与 `sources`。

**版权与引用。** 仍处于版权保护期的作品只作简短引用，不复制大段文本，不搬运剧照与插图；古典图像条目以著录与描述为主，不收录高清图版。引文以核对原文为原则，转引须注明「转引」。

**引文规范。** 古籍引文尽量对照通行整理本并注明版本；译本引文注明译者与版次；原文引语保留原词，不擅自规范化。无法确证者不补写内容，宁缺毋滥。以作品信息为主的条目可不附原文，但须注明「本条目以作品信息为主，无原文引文」。

## 八、局限与后续

其一，语种限制。古希腊语、拉丁语、丹麦语与日语原文的核对有限，部分条目依赖通行译本与二手研究，译本差异可能影响编码。

其二，版本问题。古籍异文、归属争议与成书年代问题较多，部分条目只能标「版本存异」或「待核」，读者引用前须回到原书。

其三，覆盖不均。非洲、拉美与大洋洲的人鱼传统尚未系统收录，现有条目以中国、欧洲与东亚为主，跨文化比较的结论应在此范围内理解。

其四，编码的主观性。特征判断依赖编码者对文本的解读，虽有判定标准与交叉复核，仍不排除分歧。项目以标注来源与可信度的方式保留分歧，不强行抹平。

其五，持续修订。数据更新日期见 `data/schema.js` 的 `meta.dataUpdated`；新增条目须遵循《编码手册》流程，并在《数据审校报告》（`docs/data-review.md`）中登记核查情况。
